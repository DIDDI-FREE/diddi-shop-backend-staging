# S9 — Plan d’implémentation des tokens S2S dynamiques

## Objectif

Remplacer le modèle à token statique et client global par un client DiddiFreeID
distinct pour chaque service cible.

## Sous-lots

- S9-A — provider OAuth2 `client_credentials`, cache et headers S2S ;
- S9-B — configuration JSON des client IDs/secrets par cible et validation
  fail-closed hors développement ;
- S9-C — tests, documentation du contrat et journal de livraison.

## Acceptation

- chaque adaptateur cible demande une audience et des scopes dédiés ;
- un token valide est réutilisé jusqu’à son expiration ;
- aucun secret ne figure dans les logs ou le dépôt ;
- un staging sans client ID/secret complet refuse le démarrage ;
- les tokens statiques restent disponibles uniquement pour les tests ou le
  développement local.
