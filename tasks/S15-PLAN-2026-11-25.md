# Plan S15 — Stack Portainer API + MkDocs

## Objectif

Reproduire l’infrastructure documentaire observée dans DiddiGo : une stack
Portainer versionnée qui construit l’API et le portail MkDocs depuis la même
révision, puis expose le portail à Nginx Proxy Manager par un port hôte
configurable.

## Sous-lots

- A — ajouter le Compose Portainer unifié avec API, PostgreSQL, Redis et docs ;
- B — documenter les variables Portainer, le fallback par ports hôte et le
  raccordement Nginx Proxy Manager ;
- C — valider la configuration Compose et le build MkDocs.

## Hors périmètre

- accès distant à Portainer ou Nginx Proxy Manager ;
- création DNS ou certificat TLS ;
- déploiement effectif de la stack staging.
