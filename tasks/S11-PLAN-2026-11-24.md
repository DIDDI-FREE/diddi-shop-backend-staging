# S11 — alignement DiddiRewards et devise XOF

## Objectif

Mettre DiddiShop en conformité avec le contrat DiddiRewards staging dédié à
DiddiShop et verrouiller XOF comme devise unique des contrats financiers.

## Sous-lots

- [x] S11-A — remplacer les routes et payloads Rewards génériques par les
  routes `/integrations/diddishop`, avec idempotence et snapshot de version.
- [x] S11-B — brancher quote/réservation au checkout lorsque le checkout
  fournit explicitement un `rewards_campaign_id`.
- [x] S11-C — confirmer après paiement, libérer sur échec/annulation avant
  paiement et corriger après remboursement.
- [x] S11-D — imposer XOF dans les modèles financiers, les agrégats et les
  contrats DiddiPay/DiddiSend.
- [x] S11-E — tests contractuels, documentation et proposition des validations
  staging restantes.

## Points volontairement non inventés

- Le moteur « promotion pour tous » reste la propriété de DiddiRewards. Shop
  reçoit un `rewards_campaign_id` explicite ; aucune sélection automatique de
  campagne n'est créée localement.
- Le montant `professional_payout_minor` est lu depuis le snapshot métier s'il
  existe, sinon envoyé à zéro en V1 puisque la release vendeur est reportée.
- Le scope `diddirewards:benefits:release` n'est pas ajouté au client Shop : la
  route Shop staging actuelle utilise le scope de réservation.
